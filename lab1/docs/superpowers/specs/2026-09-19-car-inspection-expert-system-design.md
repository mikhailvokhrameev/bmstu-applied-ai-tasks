# Экспертная система технического осмотра автомобилей — дизайн

Статус: **полный черновик, ожидает проверки пользователем.**
Разделы 3–6 одобрены по ходу обсуждения; раздел 7 (тесты и документация) написан по референсу и одобрения ещё не получил.

Источник требований: `docs/tz_car_inspection_v1.0.docx`.
Референс структуры: `example/` (экспертная система классификации ПЛИС).

## 1. Цель и рамки

Учебная экспертная система на SWI-Prolog. По ответам пользователя о состоянии автомобиля
она выдаёт заключение о допуске к эксплуатации, перечень несоответствий и объяснение.
Результат носит справочный характер и не заменяет технический осмотр (п. 1, 5.8.4 ТЗ).

Ключевые требования ТЗ, определяющие дизайн:

| Требование | Пункт ТЗ |
|---|---|
| Не менее 50 пронумерованных продукционных правил (ориентир 60) | 4.2, 5.1.5, 5.8.1 |
| Не менее 15 признаков, включая 14 обязательных из п. 5.1.2 | 5.1.2 |
| Проверка допустимости ввода с повтором запроса | 5.1.3, 5.2.1 |
| Ответы живут только в пределах одного осмотра | 5.1.4, 5.2.3 |
| Классификация по 4 направлениям (заключение, группа, критичность, действие) | 5.1.7, 5.1.11 |
| Объяснение: признаки и номера правил | 5.1.8, 5.8.2 |
| Диагностика неполных и противоречивых данных без аварии | 5.1.9, 5.2.2 |
| Критическое несоответствие ведёт к «не допущен» | 5.2.5 |
| Существенные без критических — «допущен с замечаниями»; иначе — «допущен» | 5.2.6 |
| Пороги отдельной группой фактов с источником | 5.8.3 |
| Проверка базы на взаимоисключающие заключения | 5.2.4, испытание 12 |
| Кодировка UTF-8, SWI-Prolog, Windows/Linux/macOS | 5.5 |

Классы результатов:

- заключение: «допущен к эксплуатации» / «допущен с замечаниями, требуется повторный осмотр» / «не допущен к эксплуатации»;
- группа: тормозная система; рулевое управление; внешние световые приборы и световозвращатели; шины и колёса; приборы обзора и стеклоочистители; экологические показатели; прочие элементы конструкции и обязательная комплектация;
- критичность: критическая / существенная / незначительная;
- действие: эксплуатация разрешена / устранить несоответствия до повторного осмотра / эксплуатация запрещена.

## 2. Выбранный подход: двухслойный вывод

Рассмотрены три варианта:

- **A. Двухслойный вывод (выбран).**
  - Слой 1: 52 правила «признаки → несоответствие»; в каждом правиле заданы группа, критичность и текст.
  - Слой 2: 8 правил «набор степеней критичности → заключение и рекомендуемое действие», взаимоисключающих по построению.
  - Плюсы: прямо реализует п. 5.1.11, 5.2.5, 5.2.6; даёт прозрачную цепочку ответ → правило → несоответствие → заключение; взаимоисключаемость проверяется автоматически.
- **B. Плоские правила** (каждое сразу выдаёт заключение). Отклонён: группа и критичность дублируются, конфликтов между правилами много.
- **C. Прямой вывод с `assert` промежуточных фактов.** Отклонён: усложняет изоляцию осмотров (5.2.3), для задачи избыточен.

Как и в референсе, правила хранятся фактами `production_rule/N`, вывод строится через `findall` по совпавшим правилам, отчёт возвращается словарём со статусом (`ok`, `insufficient_data`, `contradiction`, `invalid_input`).

## 3. Структура проекта

```
src/knowledge_base.pl  52 правила несоответствий (P01–P52) и 8 правил заключения (V01–V08),
                       нумерованные, сгруппированные по узлам, с комментариями (5.8.1)
src/inference.pl       проверка данных, противоречия во входе, вывод, объяснение
src/expert_system.pl   диалог, start/0, show_rule_count/0
tests/                 plunit: 13 приёмочных испытаний таблицы 2 и проверка конфликтов правил
scripts/               run.sh, run_tests.sh
docs/                  модель классификации, контрольные примеры, сверка с ТЗ,
                       передача тестировщику, руководство пользователя, черновик отчёта
```

Отличия от референса:

- **Пороги привязаны к категории ТС.** Условия правил ссылаются на именованный порог (например, «люфт больше `steering_play_max`»). Значение выбирается из `threshold/5` по категории из ответов. Число правил не умножается на число категорий.
- **Критичность и группа хранятся в самом правиле.** Заключение вычисляется агрегацией по этим полям.
- **Источники порогов.** Значения берутся из ТР ТС 018/2011 (прил. 8) и ГОСТ 33997-2016. Они записаны по памяти и не сверены с оригиналами; в комментариях каждого факта помечается, что значение подтверждает команда на этапе 2 ТЗ.

`uv init` создал `src/lab1/` и пустой `README.md`; Prolog-файлы лежат в `src/` рядом, `README.md` наполняется руководством по запуску. Python-окружение (`.venv`, `python-docx`) нужно только для генерации `.docx` на этапе документации и в саму систему не входит.

## 5. Диалог и политика данных

- **Условные вопросы.** Экологические показатели спрашиваются по типу топлива: у электромобиля их нет, у бензина и газа спрашиваются CO и CH, у дизеля дымность.
- **«Неизвестно».** Ответы «неизвестно», «не знаю», `unknown`, `?` разрешены для всех признаков, **кроме категории, года и типа топлива**. От них зависят пороги и набор вопросов, поэтому они обязательны и запрос повторяется.
- **Недостаток данных.** Если найдено критическое несоответствие, заключение «не допущен» выдаётся даже при пробелах: оно обосновано и не зависит от остальных ответов (5.2.5). Если критических нет, а есть неизвестные признаки, допускающее заключение не выдаётся; система показывает найденные несоответствия и перечисляет, чего не хватило.
- **Противоречия во входных данных.** Проверяется около пяти условий, например: год выпуска позже 2026; значения CO/CH при дизеле или дымность при бензине; значения выхлопа при электро; шарниры разрушены при люфте меньше 5°. При противоречии выводится диагностика, заключение не формируется.
- **Программный вызов.** `inspect_answers/2` принимает список пар `Ключ-Значение` без диалога. Тестировщик использует его для контрольных наборов. Данные действуют только во время вызова.
- **Оговорка.** Уведомление о справочном характере результата печатается в конце любого отчёта (5.8.4).
- **Завершение.** После отчёта пользователь выбирает: новый осмотр или выход. Ответы предыдущего осмотра удаляются до и после осмотра (5.1.4, 5.2.3). Конец входного потока обрабатывается без аварии.

## 6. Пороги, шкала критичности и правила

### Шкала критичности (решение команды, не норма закона)

- **Критическая**: непосредственная угроза безопасности движения. Действие: «эксплуатация запрещена».
- **Существенная**: нарушение обязательного требования без непосредственной угрозы. Действие: «устранить до повторного осмотра».
- **Незначительная**: отклонение или малый запас до предела, на допуск не влияет.

### Пороги (`thresholds.pl`, `threshold(Имя, Категория, Значение, Единица, Источник)`)

|---|---|---|---|---|---|
| минимальная удельная тормозная сила | 0,59 | 0,51 | 0,51 | 0,51 | ТР ТС 018/2011 прил. 8, ГОСТ 33997-2016 |
| неравномерность, % (существенная / критическая) | 20 / 30 | 20 / 30 | 20 / 30 | 20 / 30 | ГОСТ 33997-2016; 30 — принято командой |

### Правила слоя 1: 52 правила «признаки → несоответствие» (P01–P52)

К — критическая, С — существенная, Н — незначительная.

| Группа | Правил | Состав |
|---|---|---|
| Тормозная система | 10 | сила ниже нормы (К); малый запас силы (Н); неравномерность: предупреждение (Н) / выше допуска (С) / выше критической (К); стояночная не удерживает (К); стояночная слабо (С для M1, M2-M3, N1; К для N2-N3); утечка привода значительная (К) / малая (С) |
| Рулевое управление | 5 | люфт в трёх полосах: 80–100 % предела (Н) / выше предела (С) / выше критического (К); шарниры изношены (С) / разрушены (К) |
| Световые приборы | 7 | фары не работают (К) / одна неисправна (С); регулировка нарушена (С); сигнальные фонари не работают (К) / частично (С); световозвращатели отсутствуют (Н для M1, N1; С для M2-M3, N2-N3) |
| Шины и колёса | 5 | протектор ниже нормы (К); малый запас протектора (Н); виден корд (К); повреждены (С); нет крепёжных элементов (К) |
| Обзор и очистители | 6 | трещина в зоне водителя (К); сколы (Н); очистители не работают (К) / изношены (С); зеркала повреждены (С) / отсутствуют (К) |
| Экология | 6 | превышение CO, CH, дымности (С каждое); приближение к пределу выше 90 % (Н каждое) |
| Прочее и комплектация | 13 | ремни отсутствуют (К для года с 1991, Н для более ранних); ремни неисправны (С); аптечка отсутствует (Н); огнетушитель отсутствует (Н для M1, N1; С для остальных); знак аварийной остановки отсутствует (Н для M1, N1; С для остальных); несущие элементы: коррозия (Н) / разрушены (К); утечки: следы (Н) / капельные (С) / топливо (К) |

Правила одного признака построены **непересекающимися полосами**, чтобы одно значение не давало две разные критичности.

### Правила слоя 2: 8 правил заключения (V01–V08)

| № | Условие | Результат |
|---|---|---|
| V01 | есть критическое несоответствие (данные могут быть неполными) | «не допущен к эксплуатации» |
| V02 | есть существенные, критических нет, данные полны | «допущен с замечаниями, требуется повторный осмотр» |
| V03 | несоответствий нет или только незначительные, данные полны | «допущен к эксплуатации» |
| V04 | заключение «не допущен» | «эксплуатация запрещена» |
| V05 | заключение «допущен с замечаниями» | «устранить несоответствия до повторного осмотра» |
| V06 | заключение «допущен» | «эксплуатация разрешена» |
| V07 | критических нет, есть «неизвестно» | заключение не выдаётся, статус `insufficient_data` |
| V08 | противоречие входных данных | заключение не выдаётся, статус `contradiction` |

Всего 60 правил (ориентир ТЗ). Слой 1 один даёт 52 при минимуме 50, поэтому требование выполняется и при строгом подсчёте.
`show_rule_count/0` выводит счёт по группам и слоям; факты, пороги, подписи и служебные предикаты в подсчёт не входят (5.8.1).

### Объяснение

Цепочка «ответ → правило → несоответствие → заключение», например: «люфт 34° → P03 (рулевое управление, критическая) → V01 → не допущен». Печатаются использованные признаки и номера правил обоих слоёв (5.1.8, 5.8.2).

## 7. Тесты и документация

### Проверка конфликтов правил (5.2.4, испытание 12)

- **Слой 1.** Для каждой пары правил с общим признаком и разной критичностью тест ищет набор значений, при котором совпадают оба правила. Кандидаты берутся из порогов, границ полос ± шаг и всех перечислимых значений, для каждой категории и типа топлива. Ожидаемый результат — ни одной пары.
- **Слой 2.** Тест перебирает все сочетания «есть К / есть С / есть Н / данные полны / есть противоречие» и проверяет, что каждое даёт ровно одно заключение.
- Результаты фиксируются в таблице контрольных примеров.

### Автоматические тесты (`tests/`, plunit)

Покрывают все 13 испытаний таблицы 2 ТЗ: загрузка файла; не менее 15 признаков; отклонение неверного значения и значения вне диапазона; подсчёт правил (не менее 50 в слое 1, факты не считаются); четыре набора (исправный, с незначительными, существенными, критическими) и охват трёх заключений и трёх степеней; наличие признаков и номеров правил в объяснении; неполный и противоречивый наборы; единственное критическое несоответствие; изоляция двух осмотров подряд; UTF-8; пороги в отдельном модуле с источниками и оговорка в выводе; комментарии и комплект документации.

### Документация (`docs/`, `README.md`)

Как в референсе: модель классификации, контрольные примеры (графу «приёмочный результат» заполняет тестировщик), сверка с ТЗ по пунктам, передача тестировщику, руководство пользователя, README. Дополнительно: черновик отчёта до 10 страниц для технического писателя. Генерация `.docx` — через `python-docx` в `.venv`, по необходимости.

### Скрипты

`scripts/run.sh` и `scripts/run_tests.sh` запускают программу и тесты; основная команда `swipl -q -s src/expert_system.pl -g start -t halt` от оболочки не зависит (Windows, Linux, macOS).

## 8. Принятые решения по ходу обсуждения

- Классификация задачи: архитектурная (новый проект без существующего кода).
- Среда: SWI-Prolog 10.0.2 установлен через Homebrew, версия совпадает с референсом.
- Документация: как в референсе плюс черновик отчёта.
- Категории ТС: M1, M2-M3, N1, N2-N3 (без прицепов и мототранспорта).
- Не входит в первую версию (YAGNI): шарниры рулевого привода отдельно от общего признака, гидроусилитель, ABS, прицепы, периодичность осмотра.

## 9. Риски

- **Точность порогов.** Числа записаны по памяти и должны быть сверены с ТР ТС 018/2011 (прил. 8) и ГОСТ 33997-2016. Ошибка в значении меняет результат осмотра, но не структуру системы: пороги лежат в одном файле.
- **Шкала критичности.** Разбиение на критическую, существенную и незначительную — решение команды (п. 10 ТЗ допускает уточнение формулировок правил по согласованию с руководителем).
