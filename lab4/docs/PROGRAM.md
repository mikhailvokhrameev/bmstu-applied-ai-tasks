# Описание программы

bridge.py / owl_bridge — OWL API, HermiT и изолированное построение кандидата;
metrics.py — M1–M6, ri и F; validator.py — полная последовательная проверка;
proposals.py — строгий JSON/OWL-парсер, запросы Ollama и отдельного embedding-backend;
embedding_server.py — закреплённый локальный SentenceTransformer;
paths.py — пути репозитория и канонического комплекта;
runtime.py — сборка адаптеров и накопление дельты; search.py — эволюционный поиск;
journal.py — журнал, checkpoint, resume и replay; analysis.py — статистика и PNG;
prepare.py — инвентаризация онтологии, сверка SHA-256 локальных весов с API
и калибровка порога на проверенных ИИ парах с отдельным holdout;
release.py — проверяемый технический экспорт и изолированная локальная приёмка
OWL API/HermiT, которая не подменяет экспертное решение и GUI-проверки.
Вход — неизменяемое ядро lab2/ontology/videocard.owl (в каноническом комплекте
ontology/1.0.0/videocard.owl), параметры поиска и явно согласованный services.
Пути определяет paths.py; namespace lab4.optimizer доступен в обоих расположениях.

на 127.0.0.1:11435 и intfloat/multilingual-e5-large-instruct через отдельный
SentenceTransformer на 127.0.0.1:11437, revision
274baa43b0e13e37fafa6428dbc7938e62e5c439, MPS. Инструкция STS
«Retrieve semantically similar text.» применяется одинаково ко всем текстам.
Калибровка concept_pairs_context.csv и независимый concept_pairs_holdout.csv
зафиксированы до выбранной подготовки; порог серии 0.960735025415394.

`a39eec24440de1545432117db3d925c1d72da02222adb3e749dc30727e8d0ab4`.
Допуск Т04 описан в [qualification-v4.json](../assessment/evidence/qualification-v4.json);

Фаза хранится отдельно в metadata: debug — начальное поколение и три следующих,
34 оценки; main — 20 следующих поколений, 170 оценок. Debug допускает
`acceptance_approved=false`; main требует явного `acceptance_approved=true`.
Подготовка конфигурации и debug не устанавливают это подтверждение автоматически.
При resume фаза восстанавливается из metadata, при анализе бюджеты проверяются
для соответствующей фазы. Debug нельзя включить в основные серии.

В debug-отчёте `t04` доля корректно разобранных первых ответов считается среди
вызовов генератора модели, без crossover. У первой попытки должен быть ответ
и не должно быть parse_error/service_error; успешная повторная попытка
первый ответ не исправляет. Доля валидных онтологий рассчитывается отдельно
среди всех оценок. Проекция длительности на 170 оценок из debug (`170/34`)
является оценкой одного запуска и не подтверждает восьмичасовой предел
всей серии из пяти запусков (ТЗ, п. 4.8.2).

Требования заданы исходным [ТЗ v1.0](../tz_videokarta_lr4_nn_v1.0.docx).
Фактическое прохождение испытаний фиксируется в протоколе; наличие программы
и методики само по себе не подтверждает приёмку.

Полный исполняемый шаблон запроса: [proposal.txt](../optimizer/prompts/proposal.txt).
render_prompt подставляет Manchester-представление текущего кандидата, M1–M6,
шесть ri, предыдущую ошибку, накопленную дельту, фактические нарушения,
таблицу DIRECT/MIRRORED для текущих P13 и сохранённую оценку родителя.
Оценка родителя находится после полного Manchester и примеров: одинаковые
фактические контексты сохраняют общий префикс при разных ID. Мутация передаёт
уже вычисленные status/code/F родителя, без дополнительной валидации;
initial отмечает immutable_core без выдуманной новой проверки.
Параметры Ollama: temperature=0.7, top_p=0.95,
num_predict=2000, num_ctx=32768 и отдельный seed мутации из RNG запуска. Максимум три попытки разбора.
Исполняемый источник — proposal.txt; ниже приведена его полная копия. При правках
шаблона после завершения текущего debug необходимо синхронно обновить эту копию.

ControlGenerator с новым полным inventory из prepare поддерживает все виды
изменений таблицы 4: подклассы, определяемые классы, новые свойства данных,
характеристики и иерархии свойств, обратные свойства, условные значения для
существующих учебных индивидов, DisjointClasses и отмену прежних добавлений.
Для inverse inventory содержит object_property_domains/object_property_ranges:
новое свойство зеркально получает все явные именованные domain/range прямого.
Шаблон доступен, если вместе с InverseObjectProperties они занимают не более
пяти логических аксиом. Для значений используются individuals (U01–U08)
и teaching_class; добавляется комментарий об условных учебных данных.

Выбранный series-v1.yaml содержит полный inventory из prepare, включая
maps domain/range, teaching_class и individuals. Первоначальный local-debug.json
с тремя группами сущностей сохранён как история; в нём inverse и teaching_value
недоступны. Отмена в контроле выбирает только ранее добавленную логическую
аксиому, декларация/аннотация отдельно не расходует нулевой логический шаг.
Каждый результат шаблона проходит общий валидатор и semantic duplicate checker.

SemanticDeduplicator сравнивает точный текст «метка. комментарий» внутри категории,
включая новые сущности между собой. Кеш валидных embeddings разделён по endpoint,
модели, инструкции, категории и тексту; ошибочные ответы не кешируются. Генерация
и embeddings имеют независимые endpoint. Полная parser-диагностика сохраняется
в журнале, модели для retry передаётся компактная ошибка с проблемной аксиомой.
Исходный ответ не исправляется постобработкой и остаётся в аудите.

## Предложение модели

Ровно три JSON-поля: rationale — непустая строка; add и remove — массивы непустых
строк OWL Functional Syntax, по одной аксиоме в строке. Пример формы:

```json
{"rationale":"Обоснование изменения на русском языке", "add":["SubClassOf(:A :B)"], "remove":[]}
```

Это пример формы, а не готовый валидный кандидат. Префиксы :/owl:/rdfs:/xsd:
или полные IRI; суммарно 1–5 логических аксиом. Повторные поля JSON, повтор аксиомы,
пересечение add/remove и посторонние поля запрещены. Полная валидность проверяется
отдельно: например, новым сущностям нужны русские label/comment. Мутация модели
изменяет родителя, итоговая дельта всегда относительно исходного ядра.

## Диагностика

Последовательность первых кодов отказа: OWL2_DL, CONSISTENCY, QUERIES,
NEGATIVE_TESTS, CORE, FORBIDDEN, ANNOTATIONS, DUPLICATE, GROWTH / RELATIVE_METRIC;
дополнительное ограничение вида изменения — CHANGE_KIND. Конкретная причина
сохраняется вместе с кодом. Недопустимый кандидат: status=invalid, F=0.
Инфраструктурная ошибка: status=error, F=None; TIMEOUT или VALIDATION_ERROR;
её нельзя считать улучшением/ухудшением онтологии. Ошибка формата предложения
после трёх попыток расходует одну невалидную оценку; недоступность модели прерывает
запуск и сохраняется отдельно. bridge также может выдать CORE_REMOVAL до валидации.

Доставленный Ollama-ответ с done=true и done_reason=length проходит обычный
синтаксический разбор: при ошибке отправляется обратная связь и используются
оставшиеся попытки (не более трёх всего). Само исчерпание длины не является
инфраструктурным отказом. Ответ с done=false считается неполным ответом сервиса,
сохраняется с исходным JSON и прерывает запуск без расхода оценки.

Локальные P04/P08/P10/P11/P13/P22 — собственные явно описанные эвристики,
а не результат веб-OOPS!. Их определения, Q0=10, точные базовые дроби и пример F
находятся в [методике](../assessment/METHODOLOGY.md). Для исходника F0=1;
эти значения относятся к исходнику и эталонам, не к результатам экспериментального поиска.
