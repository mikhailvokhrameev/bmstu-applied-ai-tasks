# Запуск и проверка программы: инструкция для демонстрации

Инструкция предназначена для демонстрации лабораторной работы №4
«Нейроэволюционное улучшение онтологии видеокарт» из Git-репозитория.
Основной сценарий: запустить программу, восстановить сохранённый результат,
проверить итоговую онтологию и выполнить тесты.

Команды ниже рассчитаны на терминал macOS или Linux с Bash либо Zsh.
В Windows используйте Linux-среду WSL с установленными в ней Python и JDK.
Выполняйте блоки по порядку. Знак приглашения терминала вводить не нужно.
Все команды, кроме первоначального скачивания, выполняются из корня
репозитория — папки, в которой находятся `lab2` и `lab4`.

## 1. Подготовьте необходимые программы

| Программа | Для чего нужна | Версия |
|---|---|---|
| Git | Скачать проект | Актуальная установленная версия |
| Python | Запустить программу и тесты | Рекомендуется 3.11; минимум 3.10 |
| JDK | Читать онтологию и проверять её логическую корректность | 17, включая `java` и `javac` |
| Bash и curl | Скачать Java-библиотеки | Доступны в терминале |
| Protégé | Показать онтологию в графическом интерфейсе, по желанию | 5.6.9 |

Для короткой демонстрации нужны Python, JDK и библиотеки проекта.
Сохранённые результаты воспроизводятся без Ollama, E5 и весов нейросетей.
Интернет требуется при первом скачивании проекта и зависимостей.

Проверьте установленные программы:

```sh
git --version
python3.11 --version
java -version
javac -version
bash --version
curl --version
```

Ожидается Python `3.11.x`, а также Java и javac `17.x`.
Если Python 3.11 установлен под именем `python3`, проверьте `python3 --version`
и далее замените только команду `python3.11` на `python3`.
Системный Python 3.9 для проекта не подходит.

Если программы отсутствуют, установите Python с [python.org](https://www.python.org/downloads/)
и JDK 17 с [adoptium.net](https://adoptium.net/temurin/releases/?version=17),
затем откройте терминал заново.

## 3. Подготовьте Python и Java

```sh

```

Если папка `.venv` уже подготовлена, повторно создавать её не требуется.


Ожидается версия Python `3.11.x` либо другая поддерживаемая версия от 3.10.
Теперь команда `python` использует среду проекта.

На подготовленном компьютере проекта можно подключить уже скачанный JDK:

```sh
export PATH="$PWD/.local-runtime/jdk-17.0.21+9/Contents/Home/bin:$PATH"
java -version
javac -version
```

Этот путь относится к подготовленной macOS-среде и не входит в Git-репозиторий.
Если у вас уже работают `java` и `javac` версии 17, менять `PATH` не требуется.

Установите зависимости для демонстрации:

```sh

```

Первая команда устанавливает библиотеку построения графиков `matplotlib`
и её зависимости. Вторая скачивает закреплённые библиотеки OWL API и HermiT,

Уже проверенные Java-библиотеки повторно не скачиваются.

Признак успешного завершения второй команды:

```text

```

## 4. Запустите интерфейс программы

```sh
python -m lab4.optimizer --help
```

Ожидается справка с командами `run`, `resume` и `replay`.
Для демонстрации далее используется `replay`: восстановление кандидата
по сохранённому журналу и проверка совпадения результата.

Что пояснить при показе: «Python управляет программой, а Java-библиотеки
обрабатывают онтологию и выполняют логические проверки».

## 5. Воспроизведите лучший результат автоматического поиска

```sh
python -m lab4.optimizer replay \
  --run-dir lab4/runs/series-v1/model-102 \
  --candidate 120
```

`--run-dir` задаёт папку сохранённого эксперимента.
`--candidate 120` выбирает кандидата №120 из его журнала.
Программа заново собирает кандидата из исходной онтологии и записанных изменений,
сверяет аксиомы и пересчитывает целевую оценку.

Ожидаемый результат:

```json
{"candidate": "120", "axioms_match": true, "F": 1.3270902684891568, "matches": true}
```

`axioms_match: true` означает совпадение аксиом, `matches: true` — успешное
воспроизведение. `F` — целевая оценка качества по методике лабораторной работы.
Большее значение F означает лучший результат по этой формуле.

Здесь показан кандидат автоматического поиска. После экспертного отбора
изменений итоговая онтология имеет F ≈ `1.320714`.
Эти два значения относятся к разным версиям онтологии.
Replay не обращается к нейросетям и не повторяет проверку E5 на смысловые дубликаты.

## 6. Сравните исходную и итоговую онтологии

Скопируйте весь блок, включая первую и последнюю строки:

```sh
python - <<'PY'
from lab4.optimizer.bridge import evaluate
from lab4.optimizer.metrics import BASELINE, compute_metrics, fitness

for title, path in [
    ('Исходная', 'lab2/ontology/videocard.owl'),
    ('Итоговая', 'lab4/ontology/videocard.owl'),
]:
    result = evaluate(path, [], [])
    counts = result['counts']
    score = fitness(compute_metrics(counts), BASELINE).F
    print(f'{title}: F={score:.6f}; Q={counts["Q"]}; аксиом={counts["A"]}')
PY
```

Ожидаемый результат:

```text
Исходная: F=1.000000; Q=10; аксиом=472
Итоговая: F=1.320714; Q=4; аксиом=508
```

`Q` — число нарушений по локальной методике проверки; меньшее значение лучше.
Аксиома — формально записанное утверждение онтологии.
Добавлены 36 аксиом, описывающих шесть обратных свойств.
Например, связь «карта использует память» дополнена обратной связью
«память используется картой». Исходный файл сохраняется отдельно.

Этот блок заново вычисляет метрики файлов. Проверка логической корректности
выполняется следующим шагом.

## 7. Проверьте итоговую онтологию

Создайте временную папку для результатов:

```sh
task_demo_root="$(mktemp -d)"
echo "$task_demo_root"
```

Сохраните выведенный путь: в этой папке появятся отчёты демонстрации.
Выполните проверку:

```sh
python -m lab4.optimizer.release \
  --ontology lab4/ontology/videocard.owl \
  --evidence-dir "$task_demo_root/final-engine"
```

Команда проверяет итоговый файл и создаёт отчёт
`$task_demo_root/final-engine/acceptance.json`.
Папка `final-engine` до запуска должна отсутствовать.
Чтобы повторить проверку, сначала снова выполните блок с `mktemp -d`.

Откройте отчёт в удобном для чтения виде:

```sh
python -m json.tool "$task_demo_root/final-engine/acceptance.json"
```

Признаки успеха: `"all_passed": true` и `"passed": true` у всех семи групп
T04–T10; суммарно выполняются 138 проверок.

| Группа | Что проверяется |
|---|---|
| T04 | Корректность OWL 2 DL, согласованность и выполнимость классов |
| T05 | Совпадение ответов на контрольные вопросы с эталоном |
| T06 | Обнаружение несовместимых видов охлаждения в специальной копии |
| T07 | Обнаружение двух разных GPU при требовании ровно одного |
| T08 | Обнаружение недопустимого отрицательного объёма памяти |
| T09 | Обнаружение пропущенной связи с памятью по проверке полноты |
| T10 | Сохранение аксиом после записи и повторного чтения RDF/XML |

Это обозначения проверок движка из ЛР2; нумерация испытаний ЛР4 имеет другой смысл.
Для отрицательных испытаний программа создаёт отдельные копии с ошибками.
Успех означает, что предусмотренные ошибки обнаружены, а итоговый файл корректен.
В T09 отсутствие связи само по себе не вызывает логического противоречия:
ошибку выявляет отдельная проверка полноты данных.

Поля `accepted: false` и `gui_verified: false` в этом отчёте штатные:
команда выполняет только локальные проверки OWL API/HermiT.
Общая приёмка и проверка в Protégé подтверждены отдельными материалами
в [протоколе испытаний](ACCEPTANCE_STATUS.md).

## 8. Выполните тесты программы

Для короткого показа запустите четыре теста расчёта метрик:

```sh
python -m unittest lab4.tests.test_metrics_bridge.MetricsTests -v
```

Ожидаются `Ran 4 tests` и `OK`.
Проверяются исходная оценка, эталонные примеры и обработка недопустимых чисел.

Для полной проверки программы выполните:

```sh
python -m unittest discover -s lab4/tests -v
```

Для текущей версии репозитория ожидаются `Ran 168 tests` и `OK`,
без `FAILED` и без пропущенных тестов.
Эта проверка занимает больше времени, чем четыре теста выше;
её удобно выполнить до выступления. Тесты модельных интерфейсов используют
тестовые ответы и не загружают нейросетевые модели.

Отдельно проверьте правильность расчётов на исходнике и трёх эталонных примерах:

```sh
python -m lab4.assessment.verify_reference
```

Ожидаемая последняя строка начинается с:

```text
PASS: source SHA-256; baseline and 3 hand-counted fixtures
```

Она подтверждает контрольную сумму исходника, совпадение эталонных счётчиков,
формул метрик и оценки F, а также согласованность таблиц CSV и JSON.

## 10. Покажите онтологию в Protégé, если нужен графический интерфейс

Установите [Protégé 5.6.9](https://protege.stanford.edu/).
На подготовленном компьютере программа уже расположена в
`.local-runtime/protege-5.6.9/Protege-5.6.9`.

1. Запустите Protégé.
2. Выберите **File → Open** и откройте `lab4/ontology/videocard.owl`.
3. Выберите **Reasoner → HermiT**, затем **Reasoner → Start reasoner**.
4. Дождитесь завершения вывода; сообщения о несогласованности быть не должно.
5. Откройте вкладку **DL Query**; при её отсутствии включите
   **Window → Tabs → DL Query**.
6. Для удобного ввода имён выберите отображение сущностей по IRI:
   **View → Render by entity IRI short name (Id)**.
7. Оставьте выбранным только флажок **Instances**, введите запрос из таблицы
   и нажмите **Execute**.
8. Сравните идентификаторы найденных индивидов с таблицей; порядок не важен.

| Запрос DL Query | Ожидаемые индивиды |
|---|---|
| `CardWith8GBMemory` | U02, U03, U04, U06, U07 |
| `CardWithActiveCooling` | U02, U03, U04, U05, U07 |
| `CardWith8GBMemory and CardWithActiveCooling` | U02, U03, U04, U07 |

Класс `CardWith8GBMemory` означает объём памяти **не менее 8 ГиБ**.
Полный эталон восьми групп вопросов находится в
[expected.json](../../lab2/tests/expected.json).

Результаты OOPS! доступны в
[сохранённом сравнении](../assessment/evidence/oops-final-reference/comparison.json).
Они получены официальной локально развёрнутой реализацией OOPS REST.
Повторное обращение к публичному сервису для этого сценария не требуется.
Локальная метрика Q и число элементов в отчёте OOPS имеют разные правила подсчёта.

## Если возникла ошибка

| Сообщение или признак | Что сделать |
|---|---|
| `python3.11: command not found` | Установите Python 3.11 либо используйте проверенный `python3` версии от 3.10 |
| `No module named lab4` | Перейдите в папку с `lab2` и `lab4`, затем активируйте `.venv` |
| `No module named matplotlib` или тест пропущен из-за matplotlib | Выполните `python -m pip install -r lab4/requirements.txt` в активной `.venv` |
| `javac` не найден или Java не версии 17 | Установите полный JDK 17 и добавьте его папку `bin` в `PATH` |
| Java сообщает об отсутствующих классах OWL API/HermiT | Выполните `bash lab2/tests/harness/fetch_libs.sh` |
| Ошибка скачивания библиотек | Проверьте доступ к интернету и Maven Central, затем повторите установку |
| `File exists` при проверке онтологии | Снова создайте `task_demo_root` через `mktemp -d` и передайте вложенный новый путь |
| `CORE_CHECKSUM` или `source SHA-256 mismatch` | Проверьте `git diff -- lab2/ontology/videocard.owl` и используйте исходник без правок |
| `matches: false`, `all_passed: false` или `FAILED` | Сохраните вывод и логи; проверка не пройдена, требуется разбор указанной ошибки |
| Protégé не понимает имя класса | Проверьте отображение по короткому имени IRI, точное написание и выбранный файл |
