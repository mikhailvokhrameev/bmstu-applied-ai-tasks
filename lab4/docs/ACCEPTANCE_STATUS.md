## Производительность

Для п. 4.8.2 оценивается суммарное активное время выполнения программы по
монотонному таймеру сохранённых сессий. Календарный интервал от первого старта
до последнего завершения приводится отдельно без изменения исходных данных.
Фактические значения по timing.json всех десяти запусков:

| Серия | Активное выполнение | Календарный интервал |
|---|---:|---:|
| Основная | 10552.289027543 с (2.931191397 ч) | 37679.574867964 с (10.466548574 ч) |
| Контрольная | 1316.848423831 с (0.365791229 ч) | 1317.242971897 с (0.365900826 ч) |

По выбранному показателю активного выполнения обе серии укладываются в восемь
часов. Календарный интервал основной серии этот предел превышает; исходное
within_eight_hours=false для календарного интервала сохранено в analysis.json.
Измерения: [analysis.json](../assessment/evidence/series-v1-analysis/analysis.json)
и [сводка времени](../assessment/evidence/series-v1-analysis/timing-supplement.json).

## Независимая проверка OOPS

Используется официальный OOPS REST, развёрнутый из неизменённых upstream-исходников:
[происхождение и эталоны](../assessment/evidence/oops-reference/README.md).
Это локальный официальный сервис; он не обозначается как публичный endpoint.
На исходнике P13 совпал по десяти свойствам; дополнительный P04 для ModelComponent
объясняется различием определения связности:
[сравнение](../assessment/evidence/oops-baseline-reference/comparison.json).
Итоговая версия проверена однократно тем же официальным REST:
[запрос, ответ и метаданные](../assessment/evidence/oops-final-reference/result.json).
Получены P13=4 и P04=1; остальные четыре группы не дали нарушений.
Локальная методика даёт Q=4: разница с пятью затронутыми элементами OOPS
объясняется тем же P04 для ModelComponent. Q0 и формулы F не меняются.

## Комплект поставки

Канонический архив содержит ontology/1.0.0 и ontology/2.0.0, optimizer,
runs с десятью запусками и debug, tests, docs и README. Исполняемые среды,
веса и JAR устанавливаются отдельно. Контрольные суммы каждого файла находятся
в DELIVERY_MANIFEST.json. Проверенная распакованная копия использовала собственные
Python-зависимости; исходный репозиторий не входил в Python import path.
Все десять лучших кандидатов воспроизведены без языковой модели.
