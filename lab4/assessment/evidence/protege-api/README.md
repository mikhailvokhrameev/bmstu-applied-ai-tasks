# Проверка в настоящем Protégé

`AcceptanceAgent.java` запускается через `premain` внутри отдельного процесса установленного Protégé. Она получает настоящие `OWLEditorKit`, `OWLModelManager` и установленный HermiT через публичные API приложения. Reflection связывает загрузчики классов OSGi; приватные API, `setAccessible`, подключение к уже запущенному процессу, системная автоматизация интерфейса и чужие окна не используются.

`run_acceptance_gui.py` компилирует helper, формирует 23 Manchester-запроса по переданному `expected.json`, сохраняет хеши входов и запускает неизменённый дистрибутив. Свойство Java `user.home` и настройки Java направлены в новый каталог результатов. Переменная окружения `HOME` не меняется.

## Запуск

Команда ниже работает из корня репозитория и распакованного канонического комплекта: пути к helper, исходной онтологии и ожидаемым ответам определяет `lab4.optimizer.paths`. Требования к среде и расположению файлов приведены в [руководстве оператора](../../../docs/OPERATOR.md).

```bash
task_assessment_dir="$(python3.11 -c 'from lab4.optimizer.paths import ASSESSMENT; print(ASSESSMENT)')"
task_core="$(python3.11 -c 'from lab4.optimizer.paths import CORE; print(CORE)')"
task_expected="$(python3.11 -c 'from lab4.optimizer.paths import EXPECTED; print(EXPECTED)')"
python3.11 "$task_assessment_dir/evidence/protege-api/run_acceptance_gui.py" \
  --ontology "$task_core" \
  --expected "$task_expected" \
  --protege .local-runtime/protege-5.6.9/Protege-5.6.9 \
  --jdk .local-runtime/jdk-17.0.21+9/Contents/Home \
  --output "$task_assessment_dir/evidence/protege-gui-NEW-RUN" \
  --launch
```

Это пример проверки исходной версии. Для финальной проверки в `--ontology` передают точный путь к экспортированному файлу версии 2.0.0 и выбирают новый каталог `--output`. `--protege` и `--jdk` должны указывать на фактически установленное ПО: JDK и Protégé не входят в канонический архив.

Каталог результатов не должен существовать. Запуск настоящего macOS GUI требует разрешения за пределами ограниченной песочницы shell. Запуск OSGi, остановившийся внутри такой песочницы, не считается GUI-проверкой. Скрипт возвращает PID нового процесса. Приложение остаётся открытым для осмотра; файл `stop-request.txt` в каталоге этого запуска завершает только его собственный процесс.

## Проверки и доказательства

- Точный исходный файл должен быть загружен в настоящий EditorKit приложения. SHA-256 сохраняется до и после проверки; исходник не сохраняется и не изменяется.
- Установленная фабрика HermiT выбирается по её фактическому ID. Helper ждёт состояния `INITIALIZED` или `INCONSISTENT` и завершения классификации. Один успешный ответ асинхронного запуска не считается результатом.
- В изолированном профиле включается установленный renderer локальных имён IRI. Поэтому фиксированные Manchester-запросы распознают документированные имена сущностей.
- Все 23 запроса выполняются через parser приложения и его текущий настоящий HermiT: 17 комбинаций параметров и шесть проверок определённых классов и эквивалентных выражений покрывают восемь контрольных вопросов.
- Те же 23 запроса выполняются в настоящей вкладке DL Query через публичные Swing-контролы: `ExpressionEditor.setText` и `Execute.doClick`. Helper ждёт обновления модели `ResultsList`, читает фактические объекты индивидов и сравнивает множества точно. Для каждого запроса сохраняются снимок настоящего окна и текст его компонентов.
- T06–T09 создаются из исходной онтологии приложения и открываются в отдельных настоящих EditorKit: одинаковый ontology ID не конфликтует между загрузками. HermiT должен признать T06–T08 противоречивыми, а T09 согласованной. Записываются asserted-аксиомы выбранного индивида и настоящая строка состояния. В T09 отсутствие asserted `hasMemory` означает неполноту при OWA; карточку полноты отдельно проверяет общий тестовый harness.
- T10 сохраняет RDF/XML через менеджер онтологии исходного EditorKit и загружает его в новый настоящий EditorKit. Полные множества аксиом, аннотации онтологии и её ID должны совпасть. Затем повторяются HermiT и оба способа выполнения всех 23 запросов.
- Метрики читаются из настоящих моделей Swing JTable. Снимки получаются через `paintAll` только собственного WorkspaceFrame приложения. Видимый счётчик классов включает `owl:Thing`, если он есть в signature: в baseline отображается 16, пользовательских классов 15.

Основной результат — `evidence.json`: проверяются поля отдельных случаев и `all_collector_checks_passed`. Один `complete.txt` не означает приёмку. В `launch.json`, TSV запросов, созданных OWL-копиях, логе приложения, снимках и текстах интерфейса сохраняются проверяемые доказательства.

Manifest и название установленного плагина HermiT сообщают `1.4.3.456`, а `getReasonerVersion()` настоящего движка — `1.4.1.432`. Оба значения сохранены без подмены.

## Проверка версии 1.0.0

[Результат версии 1.0.0](../protege-gui-baseline-trial-6/evidence.json) содержит завершённую проверку с `all_collector_checks_passed=true`: все шесть случаев прошли; все 23 ответа через API и все 23 ответа настоящего DL Query совпали с ожидаемыми множествами; оба способа повторно прошли все 23 запроса после T10. SHA-256 исходника остался `d8ac600a45ce642deee38be726ae5d0d81f9e47967a9e1bb07a66b5005ae3661`.

Визуально просмотрены метрики исходника, примеры настоящих DL Query, все четыре выбранных индивида отрицательных копий со строками состояния и последний запрос после T10. Это доказательства проверки версии 1.0.0. [Итоговая версия 2.0.0](../protege-final/evidence.json) также прошла все шесть случаев и 92 точных сравнения ответов; её [результаты и визуальная проверка](../protege-final/README.md) сохранены отдельно.

Воспроизводимый маршрут использует `AcceptanceAgent.java`, `ACCEPTANCE-MANIFEST.MF` и `run_acceptance_gui.py`.
