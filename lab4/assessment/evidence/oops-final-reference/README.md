# Проверка итоговой онтологии официальным OOPS REST

Проверен точный файл версии 2.0.0 с SHA-256
`b94f610553856340c6770c1fb0a061c3aef719ee95aae7262fa919a6ef0780bb`.
Выполнен один запрос к квалифицированному self-hosted официальному OOPS REST:
HTTP 200, Turtle-ответ разобран как RDF. Запрошены P04, P08, P10, P11, P13 и P22.

| Показатель | Исходная 1.0.0 | Итоговая 2.0.0 |
|---|---|---|
| Локальная метрика Q | 10 | 4 |
| OOPS P13: затронутых свойств | 10 | 4 |
| OOPS P04: затронутых классов | 1 | 1 |
| OOPS: сумма number_affected | 11 | 5 |

Остальные четыре запрошенные группы не содержат замечаний. Две групповые записи
OOPS не означают два нарушения: число затронутых элементов равно пяти.
Множества P13 в официальном ответе и локальной реализации совпали точно:
`gpuProducedBy`, `hasMemoryType`, `hasVideoOutput`, `producedByManufacturer`.

Единственное различие P04 — `ModelComponent`: upstream выделяет корневой класс,
не участвующий в domain/range и соответствующих сложных аксиомах; локальная
операционализация признаёт связью также именованные SubClassOf и DisjointClasses.
Локальная функция F и её зафиксированный Q0 не пересчитываются по иной
операционализации. Итоговый локальный Q=4; официальный OOPS сообщает 5 затронутых
элементов с учётом этого P04.

Область проверки — официальный OOPS, собранный из неизменённых upstream-исходников
и доступный через локальный HTTP REST. Это не ответ публичного production endpoint:
публичный HTTPS REST недоступен в проверенной среде. Подтверждение происхождения,
контрольных сумм и 12 эталонных REST-проверок приведено в
[описании сервиса](../oops-reference/README.md).

Сохранены [запрос](request.xml), [сырой ответ](response.ttl),
[HTTP/RDF-подтверждение](result.json), [разобранный отчёт](upstream-summary.json),
[локальный расчёт](local-audit.json) и [точное сравнение](comparison.json).
