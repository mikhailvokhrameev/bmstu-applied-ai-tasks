Две записи сервиса — две группировки pitfalls, а не значение Q=2.
P13-N содержит десять затронутых свойств; их множество полностью совпало
с десятью локальными P13 в `baseline-audit.txt`.

Дополнительный upstream P04 — класс `ModelComponent`. Это именованный корень
иерархии, соединённый с GPUModel/MemoryConfiguration/CoolingSystem посредством
именованных SubClassOf и включённый в DisjointClasses. Локальная явно заданная
эвристика считает достаточной связью любую логическую аксиому, содержащую
две пользовательские сущности. Официальный P04 данной версии использует
involvement в domain/range и развёрнутых сложных аксиомах вместе с признаком
корня иерархии; одних именованных подклассов здесь недостаточно. Поэтому сервис
пометил ModelComponent, а локальная операционализация — нет.

Это различие реализаций документировано, не устранено подменой результатов.
Замороженные Q0=10, метрики и F всех запусков остаются прежними.
Подробные findings и множества элементов — `upstream-summary.json`, сравнение —
`comparison.json`. Источник алгоритма — официальный
[P04.java](https://github.com/oeg-upm/OOPS/blob/11572ea6b31cba29dd3f8a443e24311652f059de/src/main/java/es/upm/fi/oeg/oops/checkers/P04.java).

Это успешная проверка **локальным официальным веб-сервисом OOPS!**.
Публичный `https://oops.linkeddata.es/rest` по-прежнему имеет ранее сохранённый
timeout; этот запрос к нему не выполнялся и не подтверждает его доступность.
